Let AI agents drive QuPath

QuPath-MCP is a QuPath extension that embeds a Model Context Protocol server inside QuPath itself. Point an MCP client at it and the agent can read image data, manage annotations and detections, run Groovy scripts and plugins, and record reproducible workflows.

Requirements

  • QuPath 0.7.0, the official release. The extension's HTTP server uses only java.base, so it runs on QuPath's bundled runtime with no extra JDK modules.
  • Git and a JDK only if you build from source. The Gradle wrapper downloads the JDK 25 toolchain automatically if it's missing.
  • Node.js (for npx) only if your MCP client is stdio-only and needs the mcp-remote bridge (Claude Desktop, older Codex).

First prompts

    
QuPath-MCP is designed so an agent inspects state before acting. Open an image
      (for example the LuCa-7color multiplex sample), then try:

    

      

        Summarize the current image, annotation hierarchy, selection, and available measurement columns.
        
get_image_info → get_viewer_state → get_selection_info → get_annotation_summary

      

      

        Run cell detection in the selected tumor annotation on DAPI and export the measurements as CSV.
        
get_selection_info → run_cell_detection → get_detection_summary → export_measurements

      

      

        Record this workflow and save it so I can replay it later.
        
start_workflow_recording → … → stop_workflow_recording → save_workflow

      

      

        Replay the workflow I saved earlier.
        
replay_workflow (no LLM needed for the replay itself)

Configuration

    
Settings resolve in order, later overriding earlier: a properties file, then
      environment variables, then -D system properties. Set them before launching QuPath.

Properties files are read from the first of ~/.qupath/mcp.properties,
      ~/qupath-mcp.properties or ./qupath-mcp.properties that exists. System
      properties use the qupath.mcp. prefix, e.g. -Dqupath.mcp.port=8080.

  






  

    
Safety

    

      
QuPath-MCP is built for local, single-user, trusted-agent use. The server binds to
        127.0.0.1 and has no authentication: anything that can reach the port can call
        every enabled tool, and run_script can run arbitrary Groovy on your machine. Don't forward or
        tunnel the port, and stop the server when you aren't using it.

    

    
To lock things down, tick the Disable options in the install settings and the
      generated launch command or properties file will include them. View capture, which sends on-screen pixels to
      the agent, is off by default. More detail in the safety guide.
